# THE LAST SIGNAL — Project Report

Offline, single-player, first-person psychological horror game for Android (Unity 6.6, URP).
Exactly three playable levels, followed by an ending and credits.

---

## 1. How to play

| | Phone (touch) | Editor / PC |
|---|---|---|
| Move | Left-side floating joystick | W A S D / arrow keys |
| Look | Drag on the right side of the screen | Mouse (click the Game view first) |
| Interact | **USE** | E |
| Run | **RUN** (toggle; stops when you stop moving) | Hold Left Shift |
| Crouch | **HIDE / CROUCH** | C or Left Ctrl |
| Flashlight | **LIGHT** | F |
| Inventory | **BAG** | I or Tab |
| Pause | **II** | Esc |

Start from `Assets/Scenes/MainMenu.unity` → **New Game**. The scene order is
MainMenu → Level01_Station → Level02_Basement → Level03_Tower → Ending.

## 2. Story and levels

| Level | Difficulty | Route | Puzzle | Threat |
|---|---|---|---|---|
| 1 – The Abandoned Station | Easy | Rainy exterior → foyer (flashlight) → reception + office (3 tape fragments, fuse, clues) → service corridor → control room → basement door | **Breaker/fuse**: fit the main fuse, set B1–B4 to match the wiring memo, pull the main lever | None (radio static, footsteps, flickering light, one shadow sighting) |
| 2 – The Underground Secrets | Medium | Maintenance corridor → storage rooms, flooded section, pump room → generator chamber → elevator | **Generator**: fit 3 parts, then run the start-up order from the maintenance card (wrong order stalls and resets) | The Echo patrols, hears noise, chases; lockers to hide in; battery drains |
| 3 – The Last Transmission | Hard | Access corridor → equipment + antenna rooms → broadcast chamber → escape route | **Frequency**: fit 3 modules, tune to **103.7 MHz** (clue in the Level 2 recording, a note and a subtitle), transmit | The Echo is more alert, fewer hiding spots, faster battery drain, short final chase |

Ending: sunrise epilogue at Maya's memorial — *"I heard you this time, Maya. Goodbye."* — then THE END and credits. No sequel hook.

## 3. Architecture

Small components under `Assets/Scripts/`, one assembly (`LastSignal.Runtime`), namespaces per folder.

| Area | Main scripts |
|---|---|
| Player | `PlayerInputRouter` (merges touch + keyboard/mouse), `PlayerController` (CharacterController walk/sprint/crouch with headroom check), `PlayerLook`, `FlashlightController` |
| Interaction | `IInteractable`, `PlayerInteractor` (camera sphere cast), `PickupItem`, `Door`, `NoteInteractable`, `ItemSlot`, `TapePlayer`, `ActionButton`, `HidingSpot`, `BatteryPickup` |
| Puzzles | `BreakerPuzzle` + `BreakerSwitch`, `GeneratorPuzzle`, `FrequencyPuzzle` |
| Enemy | `EchoAIController`, `NoiseSystem`, `NoiseEmitter`, `SurfaceNoiseZone` |
| Game flow | `GameFlowManager` (persistent: scene loading, fades, checkpoints, retry, world flags), `LevelController`, `ObjectiveManager`, `Checkpoint`, `TriggerZone`, `LevelExit`, `StoryEvents`, `FlagActivator`, `ElevatorSequence`, `FinaleSequence`, `EndingSequence` |
| Save | `GameState`, `SaveManager` (local JSON), `GameSettings` (PlayerPrefs) |
| Audio | `AudioManager` (ambience + threat loop), `SubtitleManager`, `PlaceholderClips` (generated sounds) |
| UI | `HUDController`, `StoryHUD`, `MobileInputUI`, `VirtualJoystick`, `TouchLookArea`, `MobileButton`, `SafeAreaFitter`, `SettingsPanelUI`, `MainMenuController` |

**Checkpoints and saving.** Progress is stored as world flags (`door:…`, `taken:…`, `puzzle:…`, `played:…`)
plus inventory, objective and battery. Objects restore themselves from flags on load, silently, so a reload
never repeats story events or pushes the objective backwards. Saves are local only.

**Scene building.** Every game scene is generated by editor code (`Assets/Scripts/Editor/`):
**The Last Signal → Build → Build All Game Scenes** rebuilds the Player/HUD/Echo prefabs, the main menu,
all three levels (including NavMesh bakes) and the ending. Changes to level layout are made in the
builder scripts, then the scenes are rebuilt.

## 4. The Echo (enemy AI)

One NavMesh agent with a small state machine:

| State | Behaviour | Leaves when |
|---|---|---|
| Patrol | Walks authored waypoints, pausing at each | Sees the player → Chase; hears noise → Investigate |
| Investigate | Walks to the noise | Sees the player → Chase; arrives → Search |
| Chase | Follows the player / last known position | Loses sight for a few seconds, player hides, or chase time runs out → Search; reaches the player → caught |
| Search | Wanders around the last known position | Sees the player → Chase; timer ends → Return |
| Return | Walks back to the nearest waypoint | Arrives → Patrol |
| Hunt (finale only) | Knows roughly where the player is; prowls around a hiding spot instead of camping it | Player reaches the exit |

Fairness rules: sight needs a clear line (no seeing through walls) and is reduced when crouching;
a hidden player is never seen or caught; walls muffle noise; a drone sound and a red screen-edge pulse
warn the player before The Echo arrives; catching leads to a game-over screen with **Retry Checkpoint**.

| Tuning | Level 2 | Level 3 |
|---|---|---|
| Sight range / angle | 10 m / 100° | 13 m / 120° |
| Hearing multiplier | 1.0 | 1.3 |
| Patrol / chase speed (player walks 2.2, sprints 4.0) | 1.2 / 3.2 m/s | 1.5 / 3.5 m/s |
| Search time | 7 s | 9 s |

Player noise per step: sprint 10 m, walk 4 m, crouch 1.2 m (×2 in the flooded section).

## 5. Mobile and performance decisions

- URP with **Low** and **Medium** quality presets (Android defaults to Medium; PC keeps a High preset).
  Low: 67 % render scale, no shadows, HDR off. Medium: 85 % render scale, simple hard shadows, HDR off.
- No real-time shadows from the flashlight or room lights; few lights per room; no post-processing on the camera.
- Compact indoor levels with doors and corridor bends to limit what is visible at once.
- Generated placeholder audio (no large audio files); textures are ASTC (Android default).
- 30 FPS target on phones (`AppBootstrap`), screen kept awake, landscape only, safe-area aware HUD.
- No per-frame allocations in gameplay code (cached strings, non-alloc physics queries).
- **Not yet done:** baked lighting, profiling on a real device, removing unused template packages
  (AI Inference compute shaders inflate the APK and build time).

## 6. Testing

### Automated (Unity Test Framework, Play Mode) — 12 tests, all passing

| Test | What it proves |
|---|---|
| Prefab_ReferencesAreWired | Player prefab components and references are connected |
| Move_Forward_MovesPlayer, Sprint_IsFasterThanWalk | Movement and sprint |
| Crouch_LowersHeight_AndHeadroomBlocksStanding | Crouch, and standing up is blocked under low ceilings |
| Flashlight_RequiresPickup_ThenToggles | Flashlight only works after pickup; pickup goes to inventory |
| Switch_TogglesLight_ThroughInteractor | Interactor targeting and use |
| Joystick_DragToEdge_GivesFullForwardInput | Virtual joystick output |
| Pause_FreezesTime_AndBlocksInput | Pause |
| Level1_CriticalPath_ReachesLevel2 | Whole Level 1 in order, including failed attempts (no fuse, wrong breakers, locked doors) |
| Level2_CriticalPath_ReachesLevel3 | Whole Level 2 including wrong start-up orders and the elevator lock |
| Level3_CriticalPath_ReachesEnding | Whole Level 3 including wrong frequency, non-skippable final recording, shutdown and escape; save cleared at the end |
| Echo_Chases_LosesHiddenPlayer_Investigates_AndCatches | Sight → chase; hidden player never caught; noise → investigate; catch → game over → retry |

The walkthrough tests call interactions directly; they prove the logic and scene flow, not that every
object is easy to reach by walking and aiming. That needs a human play-through.

## 8. Known limitations

- Greybox visuals and generated placeholder sounds; no voice acting (all story speech is subtitled).
- Not yet played end-to-end by a person or tested on a physical Android device; FPS unmeasured.
- Lighting is real-time only (few lights, no shadows); baked lighting is a future optimisation.
